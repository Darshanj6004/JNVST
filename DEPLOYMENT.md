# JNVST Prep Platform — Setup & Go-Live Guide

## 1. Database (Supabase)

In **Supabase Dashboard → SQL Editor**, run these files **in this order** (each one is safe to re-run):

| # | File | Purpose |
|---|------|---------|
| 1 | `supabase/schema.sql` | Tables, subjects, topics, base policies |
| 2 | `supabase/question_bank.sql` | Question management |
| 3 | `supabase/student_management.sql` | Create / edit / reset students |
| 4 | `supabase/teacher_auth_helper.sql` | Teacher login by username |
| 5 | `supabase/exam_constraints.sql` | Exam answer constraints |
| 6 | `supabase/seed_teacher.sql` | Creates the first teacher account |
| 7 | **`supabase/production_hardening.sql`** | **Required.** Security, server-side exam scoring, practice sets, settings, reports |
| 8 | **all files in `supabase/question_bank/`, in order (01 … 08)** | 2,320 questions in Marathi (every topic, easy/medium/hard) + 20 ready-made tests |

> If the database was set up earlier, run only files 7 and 8.
> To wipe all old accounts and create a fresh teacher, run the local-only
> `supabase/private/reset_users_and_create_teacher.sql` (not in Git, it contains the password) after file 7.

Then in **Authentication → Providers → Email**, turn **OFF** "Allow new users to sign up".
Student accounts are created only by teachers inside the app.

## 2. Website (Vercel)

1. Import the Git repository in Vercel (framework: Vite).
2. In **Project → Settings → Environment Variables** add:
   - `VITE_SUPABASE_URL` — from Supabase → Project Settings → API
   - `VITE_SUPABASE_ANON_KEY` — the **anon / public** key (never the service-role key)
3. Deploy.

For local development, put the same two values in `.env.local` and run `npm install && npm run dev`.

## 3. First login (teacher)

- Log in on the **Teacher** tab with the username and password from the reset script
  (or `teacher_sunita` / `Navodaya@2026` if you only ran `seed_teacher.sql`).
- **Immediately change the password** in **Settings → Change password**, and update your name and the school details.

## Question bank

The files in `supabase/question_bank/` are generated by `npm run qbank` (source in `scripts/question-bank/`).
They are split into parts of ≤ 450 KB so each one can be pasted into the Supabase SQL editor.
Run them in number order; the last file (`08_cleanup_and_summary.sql`) prints a table of questions per topic.
It is safe to run again: questions are updated in place, and questions from older versions of the bank are
removed unless students already answered them or they are used in a test.

| Subject | Questions | Topics |
|---|---|---|
| Mental Ability | 900 figure questions | All 10 official sections, 90 each (30 easy, 30 medium, 30 hard) |
| Arithmetic | 1,020 | 17 topics × 60 (the 15 syllabus topics plus Ratio & Proportion and Average), 20 per level |
| Language | 400 | 80 original Marathi passages × 5 questions, tagged by skill |

**All question text, options and explanations are in Marathi** (Devanagari numerals, Marathi units).

- Mental Ability figures are SVG files in `public/qbank/mat/`, deployed with the website. The generator checks
  geometrically that exactly one option is correct.
- Arithmetic answers are calculated by the generator, never typed by hand.
- **20 ready-made tests (सराव प्रश्नपत्रिका १–२०)**: each is a full 80-question JNVST paper
  (40 Mental Ability + 20 Arithmetic + 20 Language) with a mix of levels. No question appears in two tests.
  Schedule them from *Schedule Mock → Ready-made paper*.

These are original practice questions in the JNVST pattern, not official NVS papers. Add real previous-year
papers with *Import Excel* and fill the Source column (e.g. `JNVST 2024`).

## 4. Day-to-day workflow

1. **Students** → *Add student* (roll number + password). Students log in with their **roll number or username**.
2. **Question Bank** → add questions or *Import Excel* (download the template on that page).
   Fill the optional **Source** column (e.g. `JNVST 2024`) for previous-year papers. They then appear under
   *Schedule Mock → Ready-made paper*.
3. **Practice Sets** → create focused sets. They appear on every student's Practice page.
4. **Schedule Mock** → pick questions, the **start date/time** and the **end date/time**.
   The test **opens automatically** at the start time and **closes automatically** at the end time.
   Students see "Opens at …" until then, and the Start button unlocks by itself.
5. **Mock Tests** → shows each test's window. Use **Schedule** to change the start/end time, **Go live now** to open early,
   or **Close test** to end early. When a test closes (automatically or by you):
   - any student who did not press Submit is graded automatically,
   - students can then see the answer key and explanations on their Result page.
6. **Reports / Weak Students / Merit List**: class analysis. *Reports → Export report* downloads an Excel file.
   **Merit List → Download PDF** opens the print dialog; choose *Save as PDF* (school header, ranks, signature line).
   Students with equal marks share the same rank.
7. **Student Activity**: every student's practice regularity over the last 14 days
   (*Regular* = practised on 6+ days, *Occasional* = 2–5 days, *Not practising* = 0–1 day), sessions in the last
   7/30 days, practice accuracy, mock tests and last seen. Click **View** for one student's 30-day activity calendar,
   subject-wise accuracy, practice sets solved and full timeline. Both pages export to PDF and Excel.
8. **Practice Sets → Progress**: for each set, which students solved it, how many times and on how many days,
   best/last score, and who has **not started** (so you can remind them). Downloadable as PDF.

## 5. How the exam is protected

- Answer keys are never sent to student devices during a test. Scoring happens on the server.
- The timer is set by the server. Reloading the page or changing the device clock does not add time.
- Answers are saved automatically every few seconds and retried if the Wi-Fi drops.
  If a computer crashes, the student logs in again and presses **Resume Test**.
- Questions that are in an upcoming or live test are hidden from Practice mode.
- Deactivated students cannot log in.
- Idle sessions log out automatically (configurable in Settings). Logout never happens during an exam.

## Security checklist

Built into the database (`production_hardening.sql`):
- Row-level security on every table; students see only their own data.
- Logged-out visitors can call only the two login look-ups; all other functions need a login,
  and teacher functions check the teacher role on the server.
- Nobody can change an account's role through the app; students cannot edit their roll number,
  class or status; teacher accounts can only be edited by their owner.
- Exam attempts and scores can only be created by the server; answers can only be written while
  the attempt is open; which questions are in a test is visible only to teachers.
- `seed_teacher.sql` (public demo password) refuses to run once any teacher exists.

Built into the website (`vercel.json` headers): Content-Security-Policy, X-Frame-Options DENY
(no embedding / click-jacking), nosniff, strict referrer policy, HSTS, camera/mic/location disabled.

**Do these once in the Supabase dashboard:**
- [ ] Authentication → Providers → Email → **turn OFF "Allow new users to sign up"**.
- [ ] Authentication → Policies/Passwords → minimum password length **8**.
- [ ] Never put the `service_role` key in the website or in Git — only the anon/publishable key.
- [ ] Change the teacher password after the first login and do not share it.
- [ ] Database → Backups: confirm daily backups are on (download one before each big exam).

## 6. Exam-day checklist

- [ ] Test the lab internet; open the site on one machine and log in as a student.
- [ ] Confirm the test shows *Scheduled* with the correct number of questions.
- [ ] Students log in and wait on the **Mock Tests** page.
- [ ] At the start time the test opens by itself (students' screens update within ~20 seconds).
      Students press **Start Test Now**. (You can also press **Go live now** to open it early.)
- [ ] The test closes by itself at the end time and unsubmitted papers are graded.
